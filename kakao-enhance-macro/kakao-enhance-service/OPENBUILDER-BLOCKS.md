# OpenBuilder Blocks

기준일: 2026-03-20

이 문서는 챗봇 관리자센터에서 어떤 블록을 만들고, 어떤 발화를 연결하고, 현재 서버와 어떻게 맞물리는지 정리한 설계안입니다.

## 추천 전략

처음에는 블록을 많이 나누지 말고 `한 개 메인 스킬 블록 + fallback`으로 시작하는 편이 안전합니다.

이유:

- 현재 서버가 `등록`, `상태`, `강화`를 텍스트 명령으로 이미 구분함
- 관리자센터 쪽 파라미터 추출보다 스킬 서버 쪽 파싱이 더 유연함
- 초기 테스트 속도가 빠름

## 최소 구성

### 1. 메인 블록

- 블록명: `강화 메인`
- 연결 스킬: `enhance-skill`

발화 예시:

- `등록 실전검 3`
- `등록 내검 1`
- `상태`
- `강화 5`
- `강화 19`
- `도움말`

동작:

- 사용자가 입력한 문장을 그대로 서버의 `userRequest.utterance`로 보냄
- 서버가 `등록`, `상태`, `강화`, `도움말`을 판별

### 2. Fallback 블록

- 블록명: `Fallback`
- 연결 스킬: `enhance-skill`

발화 예시:

- 비워도 됨
- 관리자센터의 기본 fallback 블록에 연결

동작:

- 사용자가 예외적인 말을 해도 서버가 `알 수 없는 명령입니다. 도움말 을 입력하세요.`로 응답

## 확장 구성

운영이 조금 안정되면 아래처럼 나눌 수 있습니다.

### A. 등록 블록

- 블록명: `플레이어 등록`
- 연결 스킬: `enhance-skill`

발화 예시:

- `등록`
- `새 무기 등록`
- `플레이어 등록`

권장 파라미터:

- `playerName`
- `currentLevel`

이 경우 현재 서버는 아래 action 파라미터도 읽습니다.

- `playerName`
- `name`
- `currentLevel`

### B. 상태 블록

- 블록명: `현재 상태`
- 연결 스킬: `enhance-skill`

발화 예시:

- `상태`
- `현재 강화`
- `내 무기 상태`

권장 파라미터:

- 없음
- 또는 `playerId`

### C. 강화 블록

- 블록명: `강화 실행`
- 연결 스킬: `enhance-skill`

발화 예시:

- `강화`
- `강화해줘`
- `강화 19`

권장 파라미터:

- `targetLevel`
- 선택: `playerId`

현재 서버가 읽는 강화 관련 파라미터 이름:

- `targetLevel`
- `level`
- 선택 플레이어: `playerId`, `player`, `weaponId`

## 서버와의 매핑 규칙

현재 스킬 서버는 아래 순서로 해석합니다.

1. `userRequest.utterance`가 있으면 우선 사용
2. 발화가 없으면 `action.name`과 `action.params`를 조합해서 명령 생성

예:

- `utterance = "강화 19"` -> 그대로 강화 명령 처리
- `action.name = "enhance"` + `params.targetLevel = "19"` -> 내부적으로 `강화 19` 생성
- `action.name = "register"` + `params.playerName = "실전검"` + `params.currentLevel = "3"` -> 내부적으로 `등록 실전검 3` 생성

## 추천 블록 이름

- `강화 메인`
- `플레이어 등록`
- `현재 상태`
- `강화 실행`
- `Fallback`

## 추천 발화 묶음

### 메인 블록

- `등록 {이름} {숫자}`
- `상태`
- `강화 {숫자}`
- `도움말`

### 강화 블록

- `강화`
- `강화해줘`
- `목표 강화`
- `강화 {숫자}`

### 상태 블록

- `상태`
- `현재 상태`
- `현재 강화`

## 관리자센터 테스트 시나리오

### 시나리오 1. 첫 등록

1. `등록 실전검 3`
2. 기대 결과: 등록 완료 문구

### 시나리오 2. 상태 확인

1. `상태`
2. 기대 결과: `실전검의 현재 강화 수치는 3입니다.`

### 시나리오 3. 강화 요청

1. `강화 7`
2. 기대 결과: 접수 문구와 작업 ID

### 시나리오 4. 다시 상태 확인

1. `상태`
2. 기대 결과: 수치 상승 확인

## 운영 팁

- 처음엔 반드시 `메인 블록 하나`로만 붙여서 성공시키는 게 낫습니다.
- 파라미터 추출은 나중에 붙여도 됩니다.
- 주소가 바뀌면 `Skill URL`과 `Test URL`을 같이 수정해야 합니다.
- 임시 quick tunnel 주소는 영구 운영용이 아닙니다.
